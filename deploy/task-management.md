# 任务管理与 Pipeline 执行

“任务管理”统一列出对话规划和 Pipeline 目录创建的任务。任务列表可按标题搜索、按来源和最新运行状态筛选；筛选在服务器分页前完成。未创建运行的任务归入“待执行”，排队、运行及正在请求取消的任务归入“执行中”，多次运行按最新运行显示状态，保留完整运行历史。

Pipeline 是独立侧栏，技能侧栏保留 Skill 和 Method。目录中的“创建任务”锁定所选版本，并先选择本次任务的数据集和输出目录。也可不选数据集，在任务中手动绑定输入文件；输出目录必须先选定。该入口不关联当前对话，不复用或改变当前对话的数据集与输出目录。

创建后进入任务管理，沿用原有的输入绑定、参数复核、执行资源设置、dry run、确认和运行接口。创建任务不会自动提交计算。重新打开任务可继续配置，运行后查看状态、日志、产物和历史，并沿用原有取消、重试与恢复监控能力。

任务管理页的“从 Pipeline 创建任务”直接打开选择窗口，支持搜索、按处理目标或软件筛选、查看详情和版本；在选择输入输出后进入原有任务配置流程。取消选择返回原页面，不改动当前任务或对话上下文。列表使用紧凑卡片，显示来源、状态、输入、输出、运行次数及更新时间，长标题收起为两行并保留完整提示。状态判定与执行逻辑沿用原实现。

Skill、Method、Pipeline 目录均有显式“查看详情”按钮。Pipeline 草稿列表提供删除操作，删除后进入“已删除草稿”，可以恢复；已发布版本和既有任务保持独立。删除及恢复检查草稿版本，旧窗口自动保存不能重新创建已删除草稿。恢复时递增版本，避免旧编辑器覆盖恢复内容。

Pipeline 编排器在方法目录和步骤参数面板标题旁提供收起按钮。收起后的边缘按钮可重新展开；窄屏一次展示一个面板。上方不再重复提供面板切换按钮。

`GET /api/workflow-index` 保留原有字段，增加 `source`、`dataset_label`、`workspace_path`。可选查询参数 `source=pipeline|conversation`、`status=draft|active|succeeded|failed|cancelled`，空值表示全部。更新时间同时考虑任务修改和运行更新。

主站已包含上述任务管理与 Pipeline 行为。开发部署使用独立端口、数据库、输出根及 worker，不与主站同步数据库。现有两站版本和路径见 [服务器部署](server-deployment.md)。
