# 提交材料说明

以队伍收到的完整正式规则为准。下面按已提供的材料要求组织当前服务器版源码、视频和运行证据，不代表已经完成所有验收或对外发布。

## 材料目录

源码与附件分别提供：

```text
source/                   固定提交源码，含运行说明与软件配置模板
submission/
  project-info.pdf        项目名称、方向、摘要、问题来源与目标
  technical-info.pdf      AGH 作用、Agnes 模型与调用方式、软件及数据
  demo.mp4                已录制演示，另附时间索引
  evidence/               保存的真实 AGH 记录、运行关联、配置和结果
  cases/                  正常、边界、失败样例
  public/                 平台、有效链接、发布截图和发布日期
```

实际附件保存于源码目录之外。视频、会话数据库、运行输出与手工材料不提交 Git；私有凭据及受限数据不随源码分发。

## 基本与技术信息

项目名称建议“NeuroWeave · AGH 科研工作台”。参赛方向按报名表可选项填写；摘要说明科研目标、交互流程与现有实现。

技术说明应区分：AGH 负责模型循环和原生工具；NeuroWeave 提供业务契约与工作台；点击运行经 AGH 注册服务提交至 Slurm；专业软件承担实际计算。填写录像会话实际使用的 Agnes 名称、可取得的版本标识、参与环节和调用方式，不自行编造模型版本。

列出代码提交、AGH 固定提交、专业软件版本、Python 环境、Slurm 资源、输入来源和所用方法。复现入口见 [平台运行说明](README.md) 与 [软件配置](SOFTWARE.md)。

## 视频与运行证据

已有视频和 AGH 记录可以复用，先确认对应版本。给视频提供时间索引，将需求、规划、参数配置、真实执行、反馈和验证对应到记录。

为至少一条真实调用链整理索引：

| 阶段 | 应关联的材料 |
| --- | --- |
| 规划 | AGH 会话、用户目标、模型身份、真实工具调用与 workflow_id |
| 能力调用 | 规划工具的 toolUseId；执行服务的 action_id；run_id 和 Slurm Job ID |
| 反馈处理 | 同一任务下 AGH 读取状态、产物或失败的实际工具结果 |
| 结果验证 | 实际验证调用与返回、产物完整性及方法专项检查结果 |

模型工具调用与工作台服务调用分别标注。保留原始记录；脱敏副本另外标明来源、脱敏范围和哈希，不插入或重排事件。模型没有读取结果时不能写成“已核验”。

当前代码不自动在运行完成后唤起模型；若保存的轨迹缺少查询与验证，需要在同一任务关联下补齐并注明版本与时间。工作台显示成功只是执行状态，不能替代 AGH 闭环证据。

## 三类测试样例

每类建议整理一例，记录条件、预期、实际结果、版本、时间和证据位置：

- 正常：有效输入，真实软件执行成功，产物和对应质量检查可读取。
- 边界：缺失必填输入、零可执行样本或达到参数边界，确认预检/执行表现符合方法契约。
- 失败：软件非零退出、输入校验失败或调度拒绝，保存真实错误与后续处理。

可以使用对应版本的既有真实记录。不同版本的记录单独注明，旧合成演示不能冒充当前服务器版验收。

## 公开内容与可访问性

公开内容材料包含平台、有效链接、截图和发布日期；具体可接受平台按正式规则确认。未发布草稿不能作为发布证明。

回环 SSH 页面不能作为评委直接可访问的在线链接。可提供固定源码包和可复现说明；若提供在线体验，另准备评委可访问入口、演示数据和访问说明。

## 源码包

提交 reviewed commit 后，从项目根目录运行：

```bash
python scripts/package_release.py --format zip --output /absolute/path/outside-project/releases
```

包包含 Git 已提交源码、运行说明、配置模板、revision.txt 和逐文件哈希 FILES.json，另有归档 SHA-256 索引；不包含 .git、runtime、依赖环境、密钥、会话数据库或科研数据。包不是运行证据包，也不自动上传或报名。不指定 --format 时保留 tar.gz 格式。
