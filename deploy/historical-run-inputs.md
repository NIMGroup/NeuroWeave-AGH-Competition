# 从历史运行结果选择输入

同一数据集分阶段处理时，可以直接复用旧运行登记的输出。例如先为各样本生成 5TT，之后只选择重新生成 FOD 和纤维追踪，将旧 5TT 作为追踪输入，不再生成或复制 5TT。

## 操作

1. 选择原来登记的数据集，选择本次需要执行的方法，然后锁定流程。
2. 在参数调整阶段，找到对应文件输入（例如“已有 5TT 影像”），点击 **从历史运行结果选择**。
3. 选择之前运行的对应步骤输出。候选按运行时间倒序排列；每次查询 10 次历史运行，可翻页查找更早结果。
4. 核对样本匹配预览。全部样本唯一匹配后，点击 **应用到 N 个样本**；只有部分匹配时，可点击 **仅使用匹配的 N 个样本**。样本预览每页 20 项，长路径换行，底部操作保持可见。
5. 绑定其他输入，核对流程卡中的共同匹配数量和折叠的跳过原因，审阅参数并执行 Dry-run，再选择 Slurm 节点、资源和并行数量后运行。部分覆盖必须选择 **按样本运行**；节点数量和实际并行资源按共同匹配数量计算。

只需要一个已有输出的输入槽使用此入口，其他输入可继续从数据集选择或连接本次流程的上游输出。绑定后显示历史运行来源，关闭并重新打开任务仍会保留。更换原数据集需要先解锁流程。

## 匹配和检查

- 使用原运行快照中的数据集 ID、数据集路径、样本 ID 和样本相对目录核对身份，不依据 `sample_0001` 等执行目录编号推断样本。当前样本显示顺序变化不会改变对应关系。
- 只采用已经结束的运行中成功步骤登记的、与当前输入类型一致的输出。部分失败运行的成功步骤仍可使用；明确选择部分覆盖后，只运行各项已绑定输入共同满足的样本。例如 5TT 覆盖 A/B、FOD 覆盖 B/C，则整个本次流程只运行 B。
- 缺失、重复、文件类型不符、不同样本指向同一文件等情况会显示具体原因；这些样本被跳过，不创建执行步骤或 Slurm 作业。如果没有共同匹配的样本，无法提交。当前一次选择一个历史运行的一个输出组，不自动拼接多个运行的零散样本。
- 原数据集及完整样本清单保留在快照中，输出沿用原样本标识。运行面板展示输入覆盖范围；重试和后端恢复遵循原范围，跳过的样本不会被自动加入。旧接口默认仍要求全部覆盖，部分应用请求需明确携带 `allow_partial: true`。
- 预览和 Dry-run 检查路径、类型、大小和绑定后的修改时间；提交前重新核对来源及样本覆盖。执行节点读取前还会核对已有的文件 SHA-256，防止旧输出被替换后继续运行。
- 历史引用只授权已登记的具体输出，普通文件选择的数据根目录限制保持原状。Slurm 所选节点必须能读取这些原路径，当前 `/home/data` 共享输出支持跨节点读取。
- 原文件保留在原位置，平台不复制。后续任务依赖这些文件，因此不要删除或移动正在被引用的旧输出。文件变化需要重新选择、审核；不会静默改绑其他输入。
- 影像空间、配准和科学参数仍由现有方法要求及其预检决定；路径匹配本身不证明 5TT 与 FOD 已正确对齐。目录输出目前核对来源、存在性和目录修改时间，不提供完整递归内容快照保证。
- 旧运行如果缺少可恢复的样本身份或具体输出登记，将无法可靠选择；不会猜测归属。单样本旧运行可使用其原始数据集快照识别样本。

## 维护与验证

`bakend/app/historical_inputs.py` 管理来源和身份核对；`bakend/app/sample_scope.py` 统一计算审核、Dry-run 和调度使用的样本交集。输入仍沿用 `existing_path` 并附加历史引用元数据。SQLite 不需要新表或迁移。原 Skill、科学脚本及算法参数没有变化。

自动化回归：`bakend/tests/test_historical_inputs.py` 覆盖 API、修订号冲突、样本顺序、缺失和重复输出、旧存储记录、重试来源、文件替换和输入目录边界。前端回归通过 `npm --prefix frontend test` 运行，操作与 API 回归和浏览器交互验收分别确认。

服务器集成验证使用 `scripts/smoke_historical_inputs.py --root /home/data/neuroweave/smoke/<新的测试目录>`。需要显式提供已部署的共享 Worker 和 Python 配置；脚本只创建合成影像和隔离数据库，不读取生产数据库或 `.env`。它调用现有 Nilearn 方法执行两轮、每轮两个样本，在第二轮倒置样本顺序，并验证实际 Slurm Worker 读取正确的旧输出且未复制到原数据目录。证据保留在测试目录的 `evidence.json`。

添加 `--partial` 可验证部分覆盖：第一轮生成两个样本的输出，再在隔离测试目录中将 B 的合成输出改名，第二轮只为 A 提交一个作业，并检查 B 被记录为跳过、A 的原始身份和输入来源保持正确。`bakend/tests/test_partial_history.py` 还覆盖显式部分应用、多输入交集、无效和重复输出、零匹配、Dry-run、实际任务范围、资源计算、持久化恢复及失败重试；前端回归见 `frontend/tests/parity.test.mjs`。

添加 `--single` 可验证原数据集仅有一个样本的情形：使用普通单文件输入在 node03 运行，再从该运行选择历史输出并再次按样本运行。两轮都应保留原样本标识；此选项与 `--partial` 互斥。

集成脚本会提交真实 Slurm 测试作业，应在明确授权和资源可用时运行。证据写入新测试目录的 `evidence.json`，用于验证身份绑定与跨节点复用，不替代科研数据的质量检查。
