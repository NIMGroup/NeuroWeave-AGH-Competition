# 主控、按需功能 Agent 与共享事实

本分支使用统一对话入口，不再让用户切换聊天与任务模式。主控根据需求直接回答、查询或准备方案，按需启用 data、methods、runtime 三类功能 Agent。功能 Agent 使用独立模型上下文和职责工具集，查证结果进入同一套会话事实。旧客户端的 chat/task 参数兼容接收，均进入相同助手；未配置真实模型的离线演示仍使用受限入口。

## 对话流程

会话维护一个当前任务与当前方案。输入框旁的“当前任务与会话信息”可编辑用户要求、目标、范围和完成条件；“保存并更新方案”只准备新版本，计算、脚本及修改仍由用户点击运行。目标编辑采用任务版本检查；后台请求尚未停止时不能编辑或删除。用户可“确认完成并结束此目标”，也可在尚未完成时“结束目标并归档”；之后的新目标使用新身份。两种结束方式分别记录完成和主动结束，不将未运行草案、停止或失败标成计算成功。未确认、未运行及已停止的流程可主动归档，目标改过但还没重建方案也不要求先重建。请求和预检仍在进行时需先停止；计算仍在运行时需先手动停止。Slurm 暂停作业在手动结束目标时，以当前调度状态及提交标记核实其已暂停，再请求停止；等待停止确认后归档，界面等待只占用对应任务按钮。已有结果与运行记录保留，用户结束后不再自动提交旧结果核验。归档立即折叠，每个目标只展示一份只读记录；最终流程快照不随后续卡片、缓存或语言切换变化。删除已归档的当前任务记录保留消息、运行记录和输出文件。user_closure 记录结束方式、时间和原阶段；旧 user_completion 记录继续兼容。

task_id 是会话、任务管理和任务可视化共用的持久身份。managed_tasks 保存任务目标、范围与当前方案引用，managed_task_plans 和 managed_task_versions 保存从属方案及简短版本记录。流程、文件操作和脚本都进入同一任务列表；修改要求、替换脚本方案或调整输入参数更新原条目。任务管理与会话使用同一个任务卡组件和读取接口，只展示当前方案；历史消息保留说明及查询记录，旧方案放入版本记录，不重复出现运行卡。任务管理可返回原会话继续维护同一任务。

会话采用单一“当前方案工作区”：消息和实时工具记录保留说明与修订信息，不挂载流程卡，也不重复插入“查看当前方案”导航按钮。工作区在对话右侧独立滚动，输入框留在对话列；可收起，窄屏通过侧边按钮展开覆盖面板。调整窗口宽度或收起面板不卸载当前卡片，未保存的编辑保留。修改前后在同一张卡中更新；修订记录折叠展示，不再并排显示旧版流程。后台规划通过只读当前任务接口同步标识和摘要，无需加载历史消息和完整图，也不触发新规划。空消息的恢复会话仍显示当前任务。兼容历史流程时只在该工作区展示当前流程的最新有效版本，其他流程快照不能用作当前图的初始缓存。

后续补充更新同一流程 ID 的新修订，保留兼容的用户输入选择和参数，并重新审阅及预检。脚本与文件操作保留各版不可变的操作 ID、清单和授权边界，逻辑 task_id 不变。任务状态从当前目标版本和实际执行服务读取，运行记录属于任务的从属记录，准备版本不计为运行。已保存运行快照保持原版本。主控维护唯一流程契约，分别记录最终产物、必须内部生成的中间产物及明确要求的方法；方法查询与方案准备自动继承当前保存的完整契约，不要求功能 agent 再抄写目标。兼容客户端传入的局部目标或不同描述不会成为第二套契约。交付仍核验实际图的阶段与连接，独立草案不能当作已经连接的流程。旧目标路线不能覆盖新目标，未变化的原始事实和摘要继续复用。需要主控修正或用户操作的错误返回 action_owner、error_code 与具体下一步，功能 agent 当批交回问题，不通过反复变换查询参数处理责任范围外的问题。这些约束复用既有任务和选路机制，不新增模型规划阶段。

1. 后端恢复用户原文、当前授权身份、选定数据集和输出目录、持续目标及共享事实。客户端不能注入内部事实或权限。
2. 主控保存目标、范围、完成条件和预期产物；方法是可调整策略，用户决定需要准确原文引用。一般问答直接回答，操作需求先明确完成条件。
3. 主控按需分派具体问题。科学流程由 methods 根据目标和用户条件查询少量真实生产方法及必要契约；不先分派数据文件识别。data 用于用户明确的数据分析、文件整理和实际结果核查，runtime 处理具体环境问答或运行结果。科学软件配置由准备草案时按所选方法读取。
4. 功能 Agent 先复用共享事实，只补查具体缺口。查询结果以 fact_id 入库，报告按稳定 requirement_id 逐项返回 status、conclusion 和 fact_ids；自然语言措辞变化不影响问题关联。已确认、未知、部分查证、明确缺失及多重匹配分别标明。可引用同会话同授权范围内其他职责的真实事实，evidence 引用归一为 fact_id；不存在的引用保持未知，格式错误或未关联的问题不覆盖其他有效结论。缺少逐项结论不能报告调查完成，达到本批边界仍保留具体 unresolved。模型解释不能替代文件计数、覆盖状态或实际契约。发现输入和布局后不穷举无关文件；全量整理必须核实对应范围或准备运行时生成精确清单的方案。
5. 主控判断真实方法结构能否满足目标。结构确定即准备草案，关键需求歧义才澄清。未选择文件属于用户输入选择，内容和样本覆盖属于 preflight，均不触发目录循环或阻止结构方案交付。
6. methods 调用 read_method_routes，后端按照完整目标、真实端口、条件参数和用户限制组织方法。助手入口不要求 existing_inputs、文件分类或路径证据；未知外部输入由用户选择。已声明存在的输入作为起点，明确缺失的必需输入继续查找生成方法并连接到后续步骤；具体角色或路径的缺失不扩大到其他输入。声明只影响结构规划，不自动绑定文件或证明内容合格。完整图和搜索前沿保存在任务中，模型接收短摘要；达到搜索预算时按原参数继续。方法契约仍校验真实端口与图连接，科学内容留给 dry-run。
7. 文件工具准备冻结清单，Python 工具准备隔离脚本。科学流程由 prepare_workflow(route_id) 恢复真实方法图并列出输入槽；模型提供的路径只保存为建议，不能满足必需输入。用户在任务卡选择文件、共用文件或包含 {sample}、登记 subject/session 变量的批量规则，明确点击采用后才保存绑定。规则预览只展开路径，不检查全样本文件内容，也不声称输入合格。同数据集、同方法输入槽的既有规则可显式复用。
8. 主控用 finish_task(awaiting_inputs) 交付结构有效的待选择输入草案；未绑定不再被判为 blocked。用户选择输入后确定步骤、审阅参数，再手动点击 dry-run。后台预检按规则核对路径、内容、梯度和兼容性，复用未变文件的内容检查缓存；不自动寻找并采用其他输入或伴随梯度文件。默认 sample_policy=eligible，必需输入共同匹配的样本进入范围，未匹配项列明原因；all 策略要求补齐全量。预检通过并确认后仍需用户点击运行，覆盖、删除和受限原地修改继续单独确认。
9. 运行反馈回到同一任务。后端直接注入从实际服务重新读取的当前产物、版本、阶段、脚本及核验报告。主控按原目标审阅当前版本；缺具体字段才用只读 read_task_artifact 定向读取脚本、清单或日志，不通过历史检索寻找当前结果。待应用预览优先核验交付，超时收尾仍保留该预览，不能重新生成已完成步骤；后续操作仍需点击运行。

输入声明在现有选路、草案保存及交付图校验中投影为范围约束，原任务契约不累积这些派生约束。用户纠正声明后更新同一任务的版本，旧路线失效，按新边界重新选路；声明语义未变时复用路线和摘要，引用措辞变化不重启搜索。没有合法前置方法时返回具体结构缺口，不能把已知缺失项继续交给用户选文件。此检查仅使用已保存事实和登记方法图，不增加调查阶段、模型审查轮次或数据扫描。

主控可在一个工具批次分派独立问题，后端最多同时调度 data、methods、runtime 三个只读调查；依赖本批其他职责的结果时使用 depends_on，等待前置调查返回后再开始。同一职责的分派保持顺序，目标更新和方案准备构成串行边界。职责之间仍共享同一事实库。停止请求会取消并等待整个并行组退出，包括传输、目录读取与过程摘要。各 agent 的截断计数与生成预算独立维护，会话 Token 仍统一计数。

主控记录 execution_kind，区分结构化文件改动、自定义 Python 脚本和科学流程。科学方案由 prepare_workflow 自动展开真实执行单元，读取必要 Runner 路径配置，包括部署默认路径，无需额外环境模型往返。仍显式分派科学配置时，后端要求已有真实方法，同批尚未选路则自动依赖 methods；简单配置读取由后端直接返回，不对宽泛镜像或资源问题伪造已确认结论。未知方法 ID 返回确定错误并停止猜名重试，工具范围限制为当前已选方法。

科学配置与数据脚本沙箱分别存储为 runtime.scientific_configuration 和 runtime.script_configuration，返回 execution_scope。科学 Runner 使用 Python 也不套用数据沙箱的库和配额。仅已声明 Python 脚本需求、已有脚本产物或用户直接询问环境时开放 list_data_environments；普通文件改动和执行结果调查不开放配置工具。配置按所选方法、实际解析的软件路径、附属依赖以及脚本镜像和库清单生成版本，未变化跨轮复用原事实与摘要，变化时失效更新。执行状态和日志始终从实际服务读取。

方案成立与运行准备状态分开。配置缺失或未知仍保留真实流程，明确提示配置后预检并手动运行；运行提交重新检查当前必要配置，不信任旧快照。配置事实不证明路径存在、库可导入或计算成功，保留原有实际运行校验。当前方案配置取代早期推测的环境缺口，历史报告仍保存，实际执行错误不会因此被忽略。information_needs 按 owner 与 phase 区分规划、配置和执行缺口。前端软件路径填写尚未实现，后续应接入相同配置来源。

## 一套事实，分开职责

assistant_tasks 保存目标、用户决定、策略、方法候选、分派记录和带版本的产物引用。目标及完成条件是模型理解，不能覆盖用户原话或权限。旧 working_memory、查询阶段检查点及独立单 Agent 缓存已从新入口移除。

事实由同一逻辑集合维护，按会话、访问身份和选定范围隔离，以 owner=data/methods/runtime 标注分工。assistant_facts 保存查询缓存和原始 evidence 引用；assistant_fact_entities 从这些证据构建按类型合并的实体，不建立各 agent 的独立事实副本。类型包括数据布局、内容、元数据、影像序列、方法候选、方法契约、流程和运行环境。候选按方法 ID 合并；数据分页只在同一范围和扫描版本内去重，重叠页面的数量不相加，版本改变不混合。完整原始结果仍可用 fact_id 定向读取；合并记录可用 entity_id 分页读取。

assistant_fact_summaries 按授权范围、类型、内容指纹和摘要规则版本缓存。观测时间、缓存命中和索引租约不是事实内容；内容未变时复用原摘要，包括已有模型说明。实际内容、约束或覆盖状态变化才更新对应实体。模型摘要仅解释较长资料，不改写路径、端口、条件参数、计数、覆盖或权限；可选摘要失败仍使用确定性结构和原始证据。缓存减少重复压缩，摘要再次输入仍计入 token。

范围依据服务器登记的实际根目录计算，不随附加的 Prompt 描述或旧模式参数改变。历史只读证据可在相同身份、会话和可验证根目录下接入共享事实；迁移记录标为历史，补查当前版本后才复用。文件分组分页属于同一事实，已读页面完整保存，coverage.groups 可读取累计分组；不同扫描版本不混合。fact、evidence 和消息引用由同一解析器核实，不存在的引用不能关闭缺口。

assistant_evidence 保存完整工具原始结果，不进行递归字符串裁剪。活跃事实引用的证据不随普通历史窗口淘汰。原始证据与事实头是同一查证记录的存储层次；功能 Agent 的结论是解释，不另建一份权威事实。

文件事实复用核对选定路径指纹和平台修改版本，并保留有界新鲜度；影像序列额外检查已读取影像及伴随文件版本，深层梯度变化会失效该查询。方法契约按该方法的定义版本核对，候选目录按目录版本核对；运行状态重新访问对应服务。未曾读取的深层文件变化不能仅凭根目录时间立即检测，运行前仍重新核验真实输入及冻结清单，必要时定向补查。事实不构成执行授权。

目录扫描跳过符号链接并报告；显式受控只读查询可读取授权范围内的链接目标。覆盖分别表示 found、unknown、missing、ambiguous。扫描未完成不能断言文件缺失；未配置必要输入模式不能宣称全部输入齐全。

逐项结论区分 observation 和 inference。直接观测需要 checks 引用原始事实字段、准确值及 observed/all 范围；后端核对真实值及全范围覆盖，未通过的确认结论保留为 partial/unknown。引用存在、计数相等或模型解释不能证明任意语义断言。元数据快照保存全范围文件、父目录和顶层分组的去重统计；页面分组数不能相加代替整体目录数。推断的依据和局限仍由主控按原话判断，不通过反复查询相同事实消除语义不确定性。

## 上下文与压缩

保存的影像序列事实可直接提供 image、bval、bvec 路径及对应头信息，规划器按具体路径取属性，不把另一个序列的壳层或体积数混入当前输入。已知路径不需要额外查询一次文件才能用于规划。同类型输入具有不同角色时需明确 slot_id 映射，例如白质、灰质和脑脊液响应；未标明角色返回映射歧义，不能随意挑选一个文件。普通方法的唯一类型输入不因端口名称不同而失去复用资格。

事实字段支持 JSON Pointer，例如 /pattern_counts/wm_response.txt/count 和 /series/0/header/volume_count；旧点号路径在无歧义时兼容。观测 checks 已携带的有效事实引用不要求在另一列表重复填写，完整范围声明仍检查实际覆盖。当前上下文仅展示每类职责的最新分派报告，较早报告保留在数据库；历史待查问题不覆盖新核验结果。

科学方法 agent 获得 matched 路线后直接返回后端保存的选路结果，主控提交 route_id 准备流程。额外的文档或算法比较问题保持未逐项调查，不阻止已核验路线交付，也不报告所有样本已合格；共同样本覆盖由用户手动 dry-run 核实。选路完成后跳过可选压缩与再次汇报模型往返。预留收尾时间也可从已保存路线准备流程，再核验交付；实际准备失败优先显示当前错误，而非所有历史调查缺口。

产物类型目录属于完整词汇表，摘要保留全部类型 ID 和名称，仅缩短用途说明；不能像文件清单一样抽取几个样例。旧代表视图从已保存的原始证据恢复完整目录，无需重查来源。

完整事实先独立存储，再投影进模型上下文，不从聊天摘要恢复事实。方法视图保留全部端口、条件及必要参数；候选只给简短用途及输入输出类型，已知方法标识优先精确匹配，目标产物用 output_type 筛选生产方法。选定方法和排除理由保存在任务状态，不反复换同义词拓展目录。大清单只展示明确标注的样例与精确统计。上下文轮流保留各职责事实并优先选定方法，辅助契约不独占预算；放不下的完整记录通过分页索引和 read_shared_facts 读取。

inspect_data_sequences 是固定只读核验器：读取小型 NIfTI/MIF 头、同目录同 stem 的 bval/bvec、MIF 内嵌梯度及必要 JSON 字段，不读取像素或启动软件。壳层、向量和 volume 数属于具体影像序列；代表页不表示全部样本已核验，同名伴随文件缺失不证明其他命名映射不存在。登记检查不再用首个 bval 代表全数据集，混合序列或未完成扫描的全局 shell_count 保持未知。feature_states 区分 found/missing/unknown，旧布尔值只作兼容提示，处理状态不能仅凭文件名确认。

过程对话超过配置预算或遇到输出截断时，保留最近完整工具调用周期，并可调用模型生成策略、已排除方向和待办摘要。摘要标为 interpretation，引用必须存在，不能改写原始事实、用户条件或权限。摘要失败或被停止不会损坏事实库；可使用共享事实继续。

输出截断在同一次逻辑请求内有界恢复，不消耗功能 agent 的调查批次，最后一批 finish_agent 也可重试；不采用任何不完整工具调用，不启动新的来源查询。恢复时提高生成预算并仅压缩过程，不追加可选模型摘要；Thinking 保持开启。汇报引用小型准确字段，不复制整个契约或清单。连续失败保留真实事实与明确缺口，日志记录输出和各工具参数大小及指纹，便于区分思考、回复和参数膨胀。

模型过程压缩每轮最多调用三次，剩余调查时间不足时跳过可选摘要。主控、功能 Agent 和截断恢复共同受本轮时间及请求上限约束；另预留最多 60 秒用于核验和交付。一旦出现真实方案，主控优先修正影响结果的错误或 finish_task，不再追加辅助记忆整理和可选调查。超时仍返回非空说明、已保存草案和未确认缺口；未核验方案不能直接获得运行权限，已核验方案显示等待手动运行，不能显示任务完成。所有主控、功能 Agent 和摘要调用的实际 Token 统一计入会话。

## 权限、版本和验证

流程卡提供执行前输出预览，按已保存的方法契约、样本范围和运行草稿展示目录树、样本与输出目录对应关系以及动态文件名提示。预览不扫描文件系统、不创建文件、不提交计算；实际调度与预览共用输出路径规则。旧流程和旧运行保留原有平铺目录，新流程默认按样本与步骤分目录，运行设置可选择目录结构。

Dry-run、重新规划和补全依赖提交后台检查，状态保存在 operations；前端按流程恢复最新进度和停止入口，切换会话或刷新不会取消后台操作。检查不再禁用全局会话导航与消息输入，只有同一流程的冲突编辑暂时禁用。结束后更新对应流程缓存，旧版本响应不能覆盖新版本。大量检查明细按问题分类汇总并分页展开，完整报告可下载；检查完成仍不启动计算。
