# 按实际需求规划与精简流程

此功能适用于已注册能力组成的任务流程，不依赖某条对话或 DWI 专用关键词。

## 使用方式

1. 在推荐任务卡中选择要保留的方法，对不需要的步骤点击“移除步骤”。已锁定的流程先解锁；已确认的流程保持只读，至少保留一个步骤。
2. 被移除步骤不再出现在执行链中。下游对应的输入显示“已移除生成此输入的步骤”；锁定保留的流程后，在该输入处选择已有文件。
3. 文件仍按现有授权数据根目录、文件格式和样本覆盖规则校验。必需输入未补齐时不能通过参数审核、dry-run 或最终确认。
4. 移除选择随流程存入数据库。重新打开历史对话仍有效；重新规划仅在保留的能力范围内推荐方法，补全依赖也不恢复已移除步骤或替换其手动输入。

移除仅修改流程草稿，不删除数据文件。其余仍兼容的方法、参数和文件绑定会被保留，原来的参数审核和 dry-run 结果失效。新输入必须通过后续检查才可运行。

## 规划约束

语义归一化分别返回目标操作和已有输入对应的生成能力，适用于已有分割、配准、预处理信号、特征和统计结果等场景。已有输入对应的生成能力不会被关键词提示或能力树搜索重新加入，也不会自动补入依赖。明确要求重新生成的内容仍属于目标操作。

规划器检查方法及 Pipeline 的实际成员、输入输出和任务约束，避免组合流程重新引入已排除操作。例如已有 FOD/5TT 时可以绑定 `mrtrix.tckgen` 的相应输入；如需 SIFT2，再连接独立的 `mrtrix.command.tcksift2`。不能因追踪缺少输入就默认添加 FOD 或 5TT 生成。

输入来源和参数条件以当前 Method 契约为准；已有文件通过文件或历史产物绑定，生成步骤通过明确的上游输出连接。不依赖退役配方的固定顺序，也不根据旧文档补造执行参数。

模型理解不能保证永远无误。方法内部检查以已登记的执行契约和能力声明为依据，不能推断未声明的软件内部行为；用户可直接裁剪可见步骤，并选择接受已有输入的现有方法。

## 上游输出与 dry-run

例如“重新计算 FOD，再结合已有 5TT 追踪”，追踪步骤的 FOD 应引用前一步输出，无须在 dry-run 前手动提供尚未生成的文件。

Dry-run 检查上游步骤顺序、输出槽位、类型和当前参数是否会生成该输出。已有文件立即检查路径及适用的内容要求；上游输出的文件、内容和配套文件检查推迟到实际执行该步骤之前，报告会标明这一点。库调用、FSL topup 配套文件和源数据目录使用相同的阶段区分；没有新增科学算法或外部接口。

运行时仍先解析已完成步骤的真实制品，再做检查。缺失的实际文件、全零 FOD、未绑定的 ACT 5TT 或 ROI，以及不可用的软件仍会阻止执行。输入校验异常会写入失败的 dry-run 报告，而不是因未捕获异常返回 HTTP 500。

## 验证覆盖

- FOD / 5TT 生成步骤移除后，追踪保留并接受手动文件输入。
- 去噪步骤移除后，GLM 接受已有 BOLD 文件，验证非 DWI 场景。
- 不完整输入阻止审核，锁定状态和版本冲突阻止过期修改。
- 移除记录、手动输入位置和已有方法选择在数据库读取、重新规划与补全依赖后保留。
- 包含已排除 FOD 生成的组合方法不可选；已有文件绑定按当前方法的真实端口检查。
- 前端 TypeScript 检查和生产构建；服务端发布使用独立源码版本及现有数据库。
