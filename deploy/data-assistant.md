# 数据助手、授权修改与恢复

统一对话入口根据需求直接回答、查询或准备方案，用户无需切换聊天和任务模式。文件整理和 CSV/JSON 调整不要求创建流程；需要科学方法或多步科学计算时，通过主控的 prepare_workflow 调用实际规划器。旧模式参数兼容接收，但不决定执行权限。演示模式仍只支持既有演示回答和受限查询，不代替真实模型验收。

## 使用

1. 选择输入数据集。需要保存副本时再选择输出目录；纯分析和原地修改不要求另选输出目录。
2. 说明目标，例如“按元数据中的序列类型整理为 T1.nii.gz、dwi.nii.gz，保留原文件，放到输出目录”，或者“把 participants.tsv 的指定列统一格式，先让我看修改”。
3. 助手读取实际样例再选择规则。整理在后端扫描完整范围，保留父目录，同步同文件名前缀的 JSON、bval、bvec；重复采集编号为 run-01、run-02。普通文件也可按规则整理；无法确定含义时只有目标允许才按原名保留，不猜测医学类型。明确排除、未覆盖和已纳入分别统计。不会自动保证 BIDS 合规，也不会自动更新其他文件里的路径引用。
4. 查看批量卡片、文本差异、完整清单和脚本输出。操作明细默认折叠，最多显示前 100 项，完整 JSON 清单可下载。默认跳过未匹配文件；允许按原名保留时会明确计入覆盖统计。卡片可分页查看并下载完整未匹配清单。新批次保存冻结快照，缺少快照的旧批次提供明确标注的当前重新扫描结果。完整覆盖要求下，未覆盖项、冲突或规则退步会显示“方案需要完善”并阻止确认和执行。生成二进制文件时可下载新版本检查。
5. 只读目录、文件和状态查询可直接进行，其余操作必须由用户点击运行。所有新建、复制、改名和移动先显示待运行方案；覆盖、删除和数据集原地修改仍须分别勾选确认，再点击运行。不要求新增账户管理。模型没有运行、确认或恢复工具，消息中的“执行”“重新执行”或“已授权”不能启动任务。
6. 任务卡显示文件数和字节进度，可以取消脚本或撤销文件执行授权。脚本在后台运行，分析结果在完成后显示；排队和运行中不代表已经修改文件。新助手任务在运行完成后自动查询结果并接续原目标；需要后续操作时准备新的待运行方案，不自动执行。旧任务仍可点击“基于结果继续”填写后续请求。日志预览截断或达到保存上限时明确提示，并提供已保存日志下载；未保存部分无法恢复。已完成部分保留记录，点击恢复撤回本批改动；恢复前检查整个记录，任何后续文件变化都会阻止覆盖。跨文件系统改名和已有目标冲突不会自动转换成覆盖操作。

通用数据操作支持复制、文件改名、完整文本写入和备份后删除。独立复制使用受控并发，改名、覆盖和删除保持顺序执行。批次不是文件系统事务；失败或中断时不会假装全部完成，也不会自动重试。内容修改、删除保留原版本；改名记录逆向映射；生成的副本可在恢复时移除。服务启动时将进行中记录标为 interrupted，保留路径占用，需检查并恢复后释放。

修改之后请刷新文件面板；原地改名不会自动重写已有科学流程的输入绑定或运行快照。需要重新扫描数据集并核对后续流程的绑定路径。

## 多轮目标与结果核验

主控理解本轮请求并按需分派事实调查，并恢复与当前访问身份、会话、数据集和输出目录绑定的持续任务。SQLite 保存最终目标、已接受的约束、完成条件和最近操作证据，独立于自然语言历史压缩。后续追问不取消持续目标，也不会自动执行改动；明确切换目标或目录范围后不继承旧约束。客户端不能注入这份记录，任务记录不是文件授权。

每轮恢复持续目标及工作事实，在需要时核验历史任务的实时状态。主助手用 update_task_state 记录范围、完成条件、当前策略和带证据的信息缺口，也可在准备工具的 task 中记录简要目标。补充元数据不覆盖未提及的产物类型和原条件；无效辅助引用保持未确认并返回警告，不阻碍有效目标和方案保存。明确换目标时清除无关条件，仍保留同范围可复用的事实。已完成批次是历史来源，不能自动重做；修订仅针对真实待运行版本。

会话工作记忆在模型解析前保存原话。assistant_tasks 保存目标、带准确消息引用的用户决定、策略和缺口，assistant_facts 保存按职责划分的同一套事实，assistant_evidence 保存完整工具结果。服务重启或聊天历史压缩后仍可接续；需要细节时按 fact/evidence 引用读取，或检索原始消息。记录绑定账户、会话及已登记的实际根目录，不能授予运行权限；历史状态需要定向核验。详见 [共享事实与压缩](flexible-dialogue.md)。

提议前按真实目录、权限、当前版本及用户目标校验。模型可在同一循环纠正参数、改变处理方法和补齐输入；确定性校验不保证每次自然语言理解正确。查询缓存、信息缺口与进度检查用于减少重复，调查与方案构建分别有界。批量名称及对象输入统计使用query_data_files，文件属性和内容使用对应format；完整科学输入用prepare_workflow.input_bindings展开校验。脚本与文件修改仍由用户点击运行。详见[多轮对话](flexible-dialogue.md)。

整理规则随冻结批次保存。base_operation_id 用于增量添加或替换同一模式的规则，只有明确要求时移除或整组替换；match_on=stem 处理不含扩展名的匹配，exclude/priority 处理重叠，exclude_paths 记录明确排除。inspect_data_coverage 从完整未覆盖快照分组，不用第一页推断全部范围。旧批次如有对应冻结工具事件，可只读恢复原规则，不重写旧清单或授权。

助手仅自动继承同一步骤内新生成的待运行方案，或本轮明确指定、范围与模式兼容的待运行规则方案。已完成批次、其他来源和不同子集不成为隐式执行模板。`selection` 可指定相对目录、包含与排除的文件模式，以及已完成批次的输出来源；`preserved` 选择复制时源路径与目标路径相同的文件，`changed` 选择其他非删除项。来源绑定当前账户、会话和输出目录，并重新读取当前文件。`inventory_data_files` 的 `view=summary` 对完整选择返回统计、名称分组和代表样例；`view=files` 分页查看明细，`coverage.next_group_offset` 续读分组。同轮派生清单与服务端完成索引缓存最长 900 秒，后续查询仍核对来源权限；新方案重新扫描，不以查询缓存代替执行前的文件版本校验。`list_data_operation_files` 可只读查询冻结的 `preserved` 清单。

`propose_filename_transform` 对完整选择范围按顺序进行字面文本替换、去前缀和去后缀，默认仅变换文件名主体，保留扩展名与父目录。后端生成最多 100000 项准确清单，未变的名称跳过，冲突阻止运行；不要求模型枚举所有文件，不猜序列含义，不自动更新内容中的路径引用。它与规则整理、逐项文本清单、脚本配合使用，不代替任意内容变换或正则表达式引擎。

方案生成后优先核验当前版本并交付，不再追加可选调查或辅助状态整理。主控确认方案与目标一致，后端核对真实版本、冲突、覆盖、静态脚本契约及必要条件，审阅绑定准确哈希。核验通过后显示待运行卡片；存在真实问题时定向修正。调查预留收尾时间，超时保留事实和草案并明确未完成部分，未核验草案不能获得运行权限。模型自行增加的改进建议不能成为用户完成条件；完成请求不代表已经完成操作。

最终目标与本轮方法分开保存。分析报告、脚本草案、文件清单和真实执行结果使用不同产物类型；前置分析不能代替最终修改目标。平台要求先预览或先点击运行，不等于用户只要求分析。旧任务的 target_step 仅供历史追溯，新主控使用目标与带版本的产物进行判断。

## 当前默认写入边界

保留现有访问方式，不引入用户管理。权限以当前会话绑定的输出目录、服务器操作系统权限、登记目录及文件版本为边界；输出目录不能与已登记数据集重叠，不能通过符号链接、绝对路径或父目录逃逸扩大写入范围。

数据工具的 execution 默认为 preview，兼容旧参数 output；两者现在都只准备方案，不能直接执行。待运行批次有效期为 24 小时；运行前再次检查准确清单、登记目录及文件版本，改变选定输出目录会阻止旧批次继续写入。用户点击任务卡中的“运行本批操作”后才会排队执行，不完整或存在冲突的方案不能运行。后台对话核验以准备好方案为本轮完成条件，不会为达到旧的 execute 目标自动补交执行请求。

覆盖确认使用 allow_overwrite，数据集原地确认使用 allow_inplace，删除确认使用 allow_delete；它们不能互相代替。恢复被覆盖的输出文件同样需要明确确认，并保留现有的文件版本检查。脚本输入继续只读，生成的文件也不自动保存。文件面板操作同样先准备卡片、点击运行后执行；目录操作保留既有审计与回收站机制，文件批次提供版本恢复。

## 平台账户与范围

管理员在后端环境中配置 NEUROWEAVE_DATA_USERS，为账户设置密码哈希与允许的已登记数据集/输出目录 ID。先以兼容模式登记所需目录，取得 ID，再配置账户；受限账户不能自行登记新的输出目录来扩大范围。

从 bakend 目录使用后端环境运行：

    python -m app.data_auth

命令交互读取密码，输出 PBKDF2 哈希。将哈希写入服务器受保护的环境文件，不放进 Git、聊天或模型上下文。例如：

    NEUROWEAVE_DATA_USERS='{"operator":{"password_hash":"pbkdf2_sha256$<32位盐>$<64位摘要>","datasets":["ds_具体ID"],"outputs":["ws_具体ID"]}}'
    NEUROWEAVE_SESSION_SECURE=true

此示例中的占位哈希必须替换。使用 HTTPS 时启用 Secure cookie；HTTP 开发环境才设置 false。会话为 HttpOnly、SameSite=Strict，期限 8 小时；服务端只保存会话令牌摘要，并限制登录尝试。账户改动需按既有维护流程重启后端才能加载，本文不触发重启。

datasets/outputs 为具体 ID 列表，空列表不授权；星号允许对应类型的所有已登记对象。两者均为星号的管理员可管理旧会话；受限账户只能看到自身会话。旧会话不自动归属新账户。科学运行按冻结的原始范围校验，后台检查和工具记录校验归属。通用方法和 Pipeline 定义仍是平台共享目录，并非个人资源。

没有配置账户时保留原有本地访问方式，使用 local 身份和后端操作系统权限；数据集原地修改仍需确认准确清单。所有文件操作仍受后端 OS 账户权限约束，不会执行 chmod/chown 来提升访问范围。平台账户没有独立 OS 用户、独立科学作业环境或完整多租户隔离。

## 隔离 Python

配置 NEUROWEAVE_DATA_PYTHON_IMAGE 后才启用生成代码。必须使用管理员审核、预先构建的本地镜像，建议锁定镜像摘要。后端执行账户需要使用 Docker 的权限；脚本不能接触 Docker socket、平台数据库或模型密钥。没有可用容器时返回错误，不退回宿主机 Python。

deploy/data-python.Dockerfile 提供仅含 Python 标准库的基础镜像定义。构建示例为：

    docker build -f deploy/data-python.Dockerfile -t neuroweave-data-python:stdlib .

构建和设置环境变量是维护操作，需要另行执行；平台不会自动安装依赖或拉取镜像。第三方库使用 [固定依赖镜像](data-python/README.md)：table 预装 pandas、NumPy、openpyxl；imaging 包含这些库及 NiBabel。模型通过 list_data_environments 查询实际可用版本，只能选择已配置环境，不能运行时安装库。镜像按哈希锁文件预先构建，运行配置使用不可变镜像 ID；不修改后端或科学软件 Python 环境，也不向 Slurm 提交脚本。

容器使用非 root UID、只读根文件系统、无网络、无额外 capabilities，输入挂载 /input 只读，脚本 /script.py 只读。/output 和 /tmp 位于受限 tmpfs。输入树含敏感文件、符号链接或特殊文件时拒绝挂载。输入还会在执行前后核对清单。

输出通过可信 Python 导出为受限归档，宿主机只接受安全相对路径的普通文件，拒绝链接、特殊文件、重复目标及超限大小。tmpfs 不使用 docker cp 导出，参见 [Docker 的复制限制](https://docs.docker.com/reference/cli/docker/container/cp/#corner-cases)。

analysis 模式打印结果、返回日志，不生成写入清单；它仍属于脚本计算，必须点击“运行脚本”后才执行。copy/inplace 模式运行后把 /output 的文件变成可检查的新版本；检查并再次点击“运行本批操作”才写入目标目录，覆盖、删除和原地确认按实际清单判断。inplace 保持相对路径，脚本不能删除输入。任务卡显示脚本、环境、配额和执行日志。

需要脚本计算改名、复制、文本修改或删除清单时，使用 `result_kind=changes`，提前声明 `change_actions`，并保留实际文件操作步骤的来源、模式和动作。脚本仅向 `/output/changes.json` 写入 `{"edits":[{"action":"rename","path":"old.txt","destination":"new.txt"}]}`，不能混合其他输出文件。后端验证最多 100000 项、32 MiB 的完整 JSON，拒绝未声明动作、选择范围外的来源和不安全路径，再按既有目录、冲突与文件版本规则生成冻结清单。同一任务卡从脚本预览转为待运行文件操作；第一次点击只计算清单，第二次点击才应用改动。空清单只完成分析。原脚本哈希不能授权后续文件清单，覆盖、删除和原地修改分别确认。默认 `result_kind=files` 保持旧的生成文件行为与授权兼容。

POST /api/data-operations/python 只保存 pending 脚本方案，兼容 background 和 execution 参数，但任何值都不启动脚本。用户运行按钮调用 POST /api/data-operations/{id}/run-script，携带 confirmed=true、conversation_id 和 script_plan_hash。授权绑定准确代码、目录、环境、库和资源配置；过期或改变后拒绝启动，重复点击不重新运行。手动启动后使用原后台队列；脚本输出文件再经 /confirm 的 manifest_hash 与独立权限提交。运行入口不暴露给模型，待运行脚本不会因刷新页面或服务重启自动启动。

脚本方案保存并绑定本轮 `selection`。`inplace` 运行后生成的每个文件路径必须落在该选择范围，越界时失败且不生成可执行清单。选择条件限制修改范围；容器输入仍挂载选定来源目录的完整只读树，不构成单独的读取权限隔离。旧脚本请求缺少选择字段时按全范围解释，保留原代码和手动确认哈希。

## 限制、记录与验证

- 扫描最多 100000 项；后端扫描生成的整理清单最多 100000 文件，外部逐项编辑请求仍最多 10000 项。超过限制拒绝生成不完整批次。目录只支持文件操作，不自动移动整棵目录。
- 文本修改最多 2000000 字符；大文本或影像调整应使用隔离脚本生成版本。页面差异显示有长度限制，完整新版本需下载核对。
- Python 提供 small、standard、extended 固定配额：分别为 60/300/900 秒、768/2048/4096 MiB 内存、512/1024/2048 MiB 输出；CPU 为 1/2/2，临时空间为 64/256/512 MiB，进程上限为 64/128/128。隔离执行器捕获前 64 KiB 日志，接口预览最多 65536 字符；达到捕获上限时标注可能不完整，只读下载仅返回绑定会话与访问身份的已保存内容。大型映射或结果应输出文件，执行清单使用 changes.json，不依赖日志。脚本最多同时运行两个，活跃数据任务上限 16；运行时取消会终止容器。大规模科学计算仍使用受审阅的 Runner/Slurm。
- 独立复制默认全局两个文件并发，NEUROWEAVE_DATA_COPY_WORKERS 可设置 1–4；队列只保留有限的在途文件。逐块复制并计算 SHA-256、检查取消；新版本发布前保留可恢复记录。字节进度包括在途数据，完成数只统计已发布文件。
- 统一助手按每段10轮模型调用或20次实际工具调用检查进展；有目标/覆盖进展时保存记忆并在同一后台请求自动继续，最多8段、80轮、160次实际调用，并受总时限约束（3002为600秒）。收束阶段仍允许少量必要只读修复，失败报告实际错误或必要事实缺口。旧受限入口保留原有预算。扫描完整不代表模型看过每个文件内容；工具输出明确分页及未匹配数量。完整机制见 [多轮对话](flexible-dialogue.md)。
- 助手输出预算由 LOCALFLOW_ASSISTANT_MAX_TOKENS 配置，恢复上限由 LOCALFLOW_LLM_MAX_GENERATION_TOKENS 指定；Thinking与答复共用生成额度。长度截断的工具调用整批丢弃，不采用部分参数；提升额度、压缩上下文后有界恢复，连续三次或本轮六次截断终止。查询已有待确认任务不会把正常追问替换成新操作确认提示。
- NFS 等共享存储若不支持 renameat2 不覆盖改名，普通文件使用同文件系统的原子硬链接发布再移除源名称，仍拒绝覆盖已有目标。两名称之间中断由数据执行记录检查并恢复。目录没有该回退，不会改用可能覆盖目标的普通改名。
- 运行中的科学输入/输出、平台存储和其他文件操作占用路径会阻止写入。预览过期或源文件变化需要重新准备，不允许静默覆盖已有目标。
- 当前执行器在单一后端进程中协调路径占用；不要以多个 API worker 同时写同一数据目录。外部程序直接写文件不参与平台锁，因此检测冲突后需重新预览或人工检查。

SQLite 分开保存任务摘要、冻结清单、每项执行记录和脚本日志；每个文件只更新自身记录及小型摘要，进度轮询不重传完整清单。旧记录读取和启动时保留原文，仅在用户明确操作旧批次时转换存储格式。SQLite 应放在本地磁盘，WAL 不适用于网络文件系统，输入输出可以位于 NFS。数据库旁的 data-operations/ 保存原版本、隔离输出与日志；应与数据库一起备份，不能只备份 SQLite 后便认为原数据可恢复。大文件原版本会占用磁盘，执行前检查备份空间。当前不自动清理版本或任务记录。

后端 test_data_operations.py 使用真实临时文件验证全量整理、权限、确认、冲突、原版本恢复、取消、中断和隔离输出。模型路由使用模拟响应验证可重复行为；真实模型质量及 Docker 镜像可用性仍需在目标环境单独验收。现有 3000/3002 部署不会因为 Git 推送自动更新。

test_assistant_task_logic.py 与 test_data_organization_revisions.py 覆盖目标跨轮次与重启保留、解释时拒绝写入、工具错误自行修正、不完整方案继续修改、覆盖退步拦截、普通文件与按原名保留、完整快照分组，以及超过一万项的后端清单。测试使用合成文件，不重放用户的大批量操作。

容器集成测试默认跳过。将 NEUROWEAVE_DATA_PYTHON_TEST_IMAGE 设置为已存在的审核镜像后，运行 pytest bakend/tests/test_data_operations.py -k configured_container，即可检查输入只读、网络禁用及 tmpfs 输出导出；不会自动构建或拉取镜像。

文件清单、整理方案和只读搜索默认跳过符号链接（Windows 同时跳过 reparse point），返回 `skipped_symlinks`、最多 50 条 `symlink_examples`、样例截断标记和 `warnings`。`complete_scan` 仅代表遍历完成；`scope_complete` 说明是否有排除，数量不包含未跟随的链接目标。只读 inventory/search 可显式设置 `follow_links=true`，仅允许当前所选数据集或输出目录内的目标，并检查每一跳、拒绝敏感/内部路径、循环和重复目标；链接查询不会扩大修改范围。文件改动仍拒绝经过链接，必须基于真实相对路径准备预览并手动运行，覆盖和删除另行确认。脚本容器输入仍执行原有严格树校验，不自动扩大挂载权限。
