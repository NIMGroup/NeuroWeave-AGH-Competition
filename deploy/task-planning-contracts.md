# 需求契约与方法图校验

规划从本轮意图与当前会话状态出发。用户可以询问方法、比较方案、检查文件、补充或修改已有流程，也可以提出独立的新目标；不能把每条追问都当作补齐上一流程缺失输入。具体对话策略见 [灵活对话](flexible-dialogue.md)。

## 需求如何约束规划

主控先保存自然语言目标、完成标准和 TaskContract.required_stages（必须在流程内完成的中间阶段），不需要填写内部产物类型。TaskContract 同时描述允许使用的已有输入、禁止复用的输入/结果、禁止操作和是否允许生成中间结果。`only_listed` 限制已有输入范围；禁止复用旧 FOD 仍可能允许从授权 DWI 重新生成 FOD。目录发现一个文件不授予复用权限。

模型归一化或结构化规划失败时记录阶段、错误类型及状态，并有限重试；认证等不可重试错误直接返回原因。诊断不记录凭据、请求正文或数据集文件内容。失败保留低置信度，不把关键词命中升级为确定需求。

## 方法如何找到

科学操作先复用用户明确声明及共享事实。输入声明通过 `update_task_state.declared_inputs` 保存准确的用户消息引用、输入类型和角色，标记为 user_declared / pending_dry_run；它不证明文件已核验，也不授予权限。已声明的输入不再分派存在性调查、不新增生成这些输入的步骤。未给路径时可留空，预检按契约中的 discovery_patterns 定位，无法唯一定位则报告具体槽的缺口。

方法 agent 先复用已有路线、选定方法和共享事实；需要选择输出时，用 `list_skill_methods(q=简短目标关键词或真实命令, limit=4)` 获取少量候选。候选的 `catalog_ref` 明确区分独立方法与组合流程，`output_refs` 给出真实方法和输出端口引用。组合流程仍通过 `read_skill_pipeline` 读取，不能把其 ID 当成独立方法 ID。端口详情在选定方法契约中，不要求浏览类型总表。

`read_method_routes.targets` 选择最终输出引用，`stage_outputs` 按 required_stages 序号选择中间阶段输出。后端从实时方法契约推导内部类型并反向搜索必要依赖；输出必须由选定方法的对应端口生成，不能由同类型的其他方法冒充。语义目标与任务 ID 不变，端口映射补充同一契约，不新增任务修订。明确的输入范围与必需阶段继续参与图校验；错端口返回实际可用端口及明确责任方，不重查文件或全库。

路线和搜索进度保存在当前任务中；相同事实复用原摘要，搜索未完成则继续原搜索。路线匹配后结束本批额外方法查询。已有匹配路线直接用 `prepare_workflow(route_id)` 恢复完整图和待预检输入规则，不由模型再次抄写连线或重复保存任务说明；真正修改目标须先 `update_task_state` 再更新路线。科学规划不读取影像头、bval/bvec、响应函数等内容；真实内容及方法条件在 dry-run 核查。

方法解释和比较保留目录查询。科学规划的候选选择限定在目标描述与真实命令，不要求预先猜类型，也不能因数据缺口反复扩大关键词搜索。能力树、精确 ID/命令及简短元数据用于回退和问答；检索接口见 [检索链路](library-upgrade.md)。

没有增加必须依赖外部 embedding 服务的检索前提。无法匹配时返回检索范围、截断或校验原因，不强制推荐首个候选，也不把预算耗尽说成平台不存在该方法。说明、操作语义和具体制品类型仍决定可检索性，泛型文件端口不能冒充已知脑区标签输出。

## 从图到可审核方案

目标规划器保存已注册方法组成的 DAG；显式图接口也接受已经核实的完整步骤。编译器检查 ID、版本、参数、条件端口、格式/类型、拓扑、外部输入范围、目标产出及无关步骤；只有通过后才生成流程卡片说明。格式声明在图编译、展开后的运行核查和文件入场时校验；容器不兼容必须使用明确登记的转换步骤，不能依赖隐式转换。

连线保留精确端口身份，例如白质/灰质/脑脊液响应不能因为类型相同而互换。参数编辑后重新计算条件输入输出，约束在锁定、审核、Dry-run 和提交时再次检查。类型兼容只证明契约关系，不证明空间对齐或影像内容正确。

已有输入以路径或定位规则及语义保存，FSL 梯度父类型按 `.bval`/`.bvec` 归一化；`bval/bvals` 等消费者端口别名不会制造新事实或触发重新选路。同类型而语义不同的响应端口仍区分。dry-run 展开全部登记样本输入，默认取必需输入共同匹配的样本并记录跳过原因；用户明确不可跳过时才采用全量严格策略。规则已准备不显示为内容已核验。

条件输入由同一份方法定义驱动规划、参数表和运行器。MRtrix 的响应估计、FOD、张量拟合、ADC、掩膜及DWI提取使用 gradient_source：auto 优先采用图像内嵌梯度，fsl 要求成对 bval/bvec，mrtrix 要求四列梯度表。仅MIF扩展名不能证明有内嵌梯度；显式外部来源会覆盖内嵌信息。图像与选用梯度数量、响应结构等在预检核查。

预检读取小型头和数值摘要，不加载图像像素、不启动科研软件。结果按实际文件身份、大小、mtime/ctime和读取器版本缓存，随工作流保存并传到计算节点。重复预检、不同步骤及运行器复用未变化的内容摘要；输入或读取器变化时重新读取相关内容。参数或输入来源变化后仍重新判断关系与条件，路径授权、执行确认始终独立检查。上游新生成文件首次可读取时核查。

同批数据调查与依赖它的科学选路按依赖顺序执行，其他独立调查可并行。共享事实返回可读字段索引；字段名错误直接返回已有摘要和实际字段名，不要求重查来源。方案保存后进入核验和交付，不再进行可选压缩。所有计算、脚本和修改仍须手动点击运行，覆盖和删除需确认。

Workflow 保存需求契约与检索/校验诊断，说明以真实步骤为依据。没有合格图时可以解释缺项、请求必要澄清，或先回答问题再提供可编辑的规划邀请；不会声称已执行或将无效图提交 Runner。

后端回归覆盖模型失败、已有输入限制、梯度子类型、错误树分支、条件端口、目标来源、额外步骤与参数编辑。检查方法见 [项目说明](../README.md)。测试不需要提交科研任务；原始问题及旧发布证据保留在 Git 历史中。
